# Graphic-First Routing

## Purpose

Force early routing toward graphic-led pages when the page meaning depends on spatial or relational logic.

## Routing Rule

Before choosing any page type, answer:

1. What cognition is this page trying to produce?
2. What must the audience see before reading?
3. Would bullets materially weaken the page?
4. Is the core meaning encoded in relation, direction, comparison, hierarchy, flow, or structure?

If the answer to question 3 or 4 is yes, route to a graphic-led page first.

## Graphic Proposition Triggers

Default to a graphic proposition page when the content involves:

- mechanism explanation
- causal chain
- multi-stage flow
- left-right comparison
- hierarchy
- system composition
- relationship map
- role boundary
- path evolution
- blocker vs enabler logic
- bridge or handoff logic
- input/output structure
- decision logic
- impact chain
- network relationship

## Routing Priority

Use this order:

1. graphic proposition page
2. graphic-plus-text page
3. data/evidence page
4. pure text or chapter page

Do not invert this order unless the user explicitly requests a text-first deliverable.

## Graphic Proposition Test

Treat the page as graphic-led if any of these are true:

- sequence matters more than prose
- spatial adjacency explains meaning
- arrows carry logic
- comparison structure matters
- layered position changes interpretation
- node relationship is the main message

## Fallback Rule

If the page probably needs a graphic but the exact shape is not yet clear:

1. stop at blueprint level
2. define `visual_center`
3. define `chart_or_diagram_goal`
4. define `svg_module_candidate`
5. define `information_loss_if_text_only`

Do not collapse to a generic issue page just because the graphic is not fully resolved.
