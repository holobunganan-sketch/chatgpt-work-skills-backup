# 伦理材料 Word 交付

## 执行边界

- 将用户指定的伦理项目目录设为工作范围，优先读取当前目录中的事实。
- 默认保留源模板，创建完成副本。用户明确要求原位填写时再修改指定文件。
- 将研究方案、知情同意书、CRF、伦理申请表、人员名单、合同和目录清单分别登记，避免混用信息来源。
- 对研究名称、申办方、研究单位、主要研究者、样本量、保存年限、版本号和版本日期执行跨文件核对。
- 保留签名、日期和机构盖章空白，除非用户提供了明确填写内容和授权。
- 将内部核对记录置于正式交付目录之外。

## 执行流程

### 1. 定位真实目录和模板

1. 核对用户给出的项目路径是否存在。
2. 路径含重复层级或无法打开时，仅枚举其父目录和必要子目录，定位实际模板。
3. 优先查找目录清单、研究方案、人员名单、申请表、声明、知情同意书、CRF 和版本化 PDF/DOCX。
4. 记录源模板路径、格式、修改时间和文件摘要值。

### 2. 建立事实来源表

按以下优先级提取信息：

1. 已确认的研究方案和正式合同。
2. 当前伦理申请主表与用户明确指令。
3. 人员名单、中心信息和项目管理表。
4. 其他说明、邮件或历史版本。

对冲突字段记录各来源、值、时间和推荐采用值。缺少可靠依据时保留空白并列入待确认项。

### 3. 选择保格式处理路径

- 标准 DOCX：优先使用结构化文档编辑，保留段落、表格、页眉页脚和页面设置。
- 严格版式 DOCX：先复制，再进行最小范围修改；修改后检查 OOXML、页数和关键位置。
- 旧版 DOC：优先调用原生 Word 兼容路径处理副本，并进行打开、分页和表格完整性检查。
- PDF：读取文本和页面图像用于取证；仅在用户要求生成可填写或修订 PDF 时修改副本。

### 4. 填写材料

1. 按字段逐项填写，保留模板原有标签和布局。
2. 使用本地材料中的正式名称和原始数值，禁止凭经验补写项目事实。
3. 对利益冲突、研究主体、资助方、样本来源和数据来源使用用户已确认口径。
4. 对重复人员表单核对姓名数量、顺序、勾选状态和签名留白。
5. 修改多个文件时建立字段一致性表，完成后逐字段复核。

### 5. 按清单整理和命名

1. 读取清单的编号、层级、材料名称和必需状态。
2. 将现有文件映射到清单条目；记录缺失、重复、待确认和额外支持文件。
3. 从文档封面或正式版本字段读取版本号与日期，禁止只沿用旧文件名。
4. 在工作副本目录中完成编号和重命名。
5. 将未列入清单的支持材料放入明确的补充区域，避免强行纳入编号序列。
6. 用户要求完整目录树时创建全部规定目录，并对空目录和缺失材料作清楚标识。

### 6. 构建正式交付

1. 创建独立交付目录或使用用户指定目录。
2. 仅放入需要提交的材料、正式目录表和用户要求的说明。
3. 排除临时文件、脚本、日志、审计报告、备份、锁文件和内部工作记录。
4. 用户要求压缩包时，从核验通过的交付目录生成压缩包，并核对包内文件数量和名称。

### 7. 验证

逐项核对：

- 所有交付文件可正常打开。
- 页面设置、表格、页眉页脚和关键版式保持完整。
- 项目名称、研究主体、资助方、中心、主要研究者、样本量和保存年限跨文件一致。
- 版本号、版本日期、文件名和正文相互一致。
- 所有要求填写的人员均已覆盖。
- 签名、日期和盖章位置按要求保留空白。
- 清单编号、文件数量、目录层级和压缩包内容与最终目录一致。
- 源模板仍然存在且摘要值未改变，用户授权原位修改的文件除外。

## 异常处理

- 路径无效：检查相邻目录，报告实际定位结果和原路径问题。
- 多份方案信息冲突：列出候选值和证据，暂停受影响字段的正式填写。
- Word 自动化接口不稳定：保留已提取信息，改用 OOXML 或原生应用的安全路径，减少重复打开次数。
- 中文文本提取异常：统一使用 UTF-8 输出，并对关键字段进行人工复核。
- 重命名命令显示成功但目录未变化：重新读取实际目录并核对每个目标文件。
- 交付包出现内部材料：移出正式目录，重新构建并复核压缩包。

## 完成判定

- 真实模板和权威事实来源已经确认。
- 所有获授权字段均已填写或明确标记待确认。
- 源文件保护和版式要求已经满足。
- 清单映射、编号、命名、版本和目录结构已经核对。
- 跨文件关键字段一致。
- 正式交付目录边界清洁，交付文件可直接提交。
