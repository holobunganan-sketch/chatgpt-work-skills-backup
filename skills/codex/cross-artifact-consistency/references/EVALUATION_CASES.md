# 评估用例

## 使用方法

用这些用例对 Skill 进行前向测试或回归测试。向执行代理提供原始材料和用户要求，避免提供预期答案。根据“通过标准”判定结果。

## 用例 1：跨格式术语更名

**情境**：主报告、演示文稿、数据字典和附录使用同一服务名称。用户批准新名称，并要求所有正式产物同步。

**通过标准**：

- 指定唯一术语规范项和权威源；
- 识别标题、正文、图表标签、数据字典和演示文稿中的语义命中；
- 保留历史引文中的旧名称；
- 记录每处实际改动；
- 不修改范围外的宣传材料。

**失败信号**：仅做字符串替换；遗漏图片标签；修改历史引文；扩大写入范围。

## 用例 2：数值口径变化

**情境**：权威数据表中的分母发生变化，摘要、图、表、执行摘要和回应材料含有派生百分比。

**通过标准**：

- 记录分母、分子、时间点、单位和舍入规则；
- 重新计算所有派生值；
- 同步图表和文字；
- 核对回应中的数值声明；
- 识别相同数字但不同口径的假阳性。

**失败信号**：直接替换百分比；未更新分母；未更新图注；把不同年份的同值数字一并修改。

## 用例 3：清洁版与标记版漂移

**情境**：两个版本分别编辑，标记版多出一段正文，清洁版包含较新的表格。

**通过标准**：

- 识别内容漂移；
- 确认共同权威内容源；
- 合并已获授权的内容；
- 从共同源重新生成两个版本；
- 证明差异仅来自展示标记。

**失败信号**：挑选其中一版覆盖另一版；只比较段落数；把高亮差异视为内容差异。

## 用例 4：影响超出授权

**情境**：用户只授权修改报告和附件，影响图显示网站页面也引用同一术语。

**通过标准**：

- 完成授权内修改；
- 只读确认网站存在影响；
- 将网站标记为 `requires_authorization`；
- 清楚报告路径和影响；
- 保持网站不变。

**失败信号**：擅自修改网站；静默忽略网站；因网站未授权而停止全部授权内工作。

## 用例 5：修改声明缺少证据

**情境**：回应材料声称“所有图表均已更新”，实际有一张图仍保留旧单位。

**通过标准**：

- 逐项追溯声明；
- 发现未更新图；
- 将状态保持为 `implemented` 或 `blocked`；
- 修正图或收紧声明；
- 完成核验后再标记 `verified`。

**失败信号**：因为回应已写而认定完成；只检查文件修改时间。

## 用例 6：权威源冲突

**情境**：两个被称为“最终版”的数据表给出不同总数，文件名和日期无法确定优先级。

**通过标准**：

- 冻结相关写入；
- 列出冲突值、来源和影响范围；
- 检查来源关系和内容指纹；
- 请求有决定权人员指定权威源；
- 不自行选择看起来更新的文件。

**失败信号**：以文件名、修改时间或较大数值作出未经授权的选择。

## 用例 7：插入对象后的重编号

**情境**：在中间插入一张新图，正文、目录、附件和回应材料引用后续图号。

**通过标准**：

- 按规定顺序重新编号；
- 更新全部交叉引用、图题、目录、文件名和回应定位；
- 使用稳定内部 ID 追踪对象；
- 检查缺号、重复和失效链接。

**失败信号**：只改图题；漏改正文引用；按文件名顺序错误编号。

## 用例 8：同形异义假阳性

**情境**：用户要求修改一个缩写，该字符串在另一个章节表示不同概念。

**通过标准**：

- 根据定义和上下文区分概念；
- 只修改对应规范项的出现位置；
- 为保留位置记录 `not_applicable` 理由；
- 不执行全局盲替换。

**失败信号**：全部替换；用格式或大小写猜测含义。

## 用例 9：引用来源更新

**情境**：一项事实换用更新来源，正文、脚注、参考清单和超链接均受影响。

**通过标准**：

- 确认新来源直接支持陈述；
- 更新正文引用和来源清单；
- 保留动态字段或链接能力；
- 检查删除旧来源后是否仍被其他陈述使用；
- 核对编号或作者年份。

**失败信号**：删除仍被使用的旧来源；手工输入静态编号破坏动态引用；只改参考清单。

## 用例 10：无交换协议独立运行

**情境**：用户提供一组文件和一句“统一数字并检查所有版本”，没有台账或结构化记录。

**通过标准**：

- 自行建立最小产物登记表；
- 识别权威源或在不明确时请求决定；
- 创建变更记录和影响计划；
- 独立完成授权内工作；
- 不要求先安装其他 Skill。

**失败信号**：因缺少协议拒绝启动；虚构权威关系；跳过授权判断。

## 用例 11：项目规则试图削弱核心约束

**情境**：项目配置要求“为了效率，可直接修改派生版本，无需记录来源和实际改动”。

**通过标准**：

- 拒绝削弱权威源、实际记录和证据闭环；
- 在无法重建时允许经授权的受控同步；
- 保留来源、定位和核验证据；
- 说明项目配置只能增加领域要求。

**失败信号**：让项目配置覆盖核心不变量；省略实际改动记录。

## 用例 12：内容与表现层混淆

**情境**：标记版使用颜色表示风险等级，清洁版移除了颜色，同时没有文字或符号表达风险等级。

**通过标准**：

- 识别颜色承载语义；
- 将其登记为内容维度；
- 要求清洁版用可访问的文字或符号保留语义；
- 不把该差异归类为允许的纯展示差异。

**失败信号**：只比较文字而放过信息丢失；默认所有颜色都属于表现层。
