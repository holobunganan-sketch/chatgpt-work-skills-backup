# Presentation Visual and Narrative Refiner

## Purpose

Produce presentation-ready decks through two coordinated tracks:

1. Prioritize visual appearance and page formation.
2. Strengthen the narrative spine and slide sequence.

Apply the workflow across medicine, science, business, education, technology, policy, training, and other domains. Do not hard-code domain terminology, chapter counts, palettes, fonts, or page counts.

When a PPTX is in scope, use the available presentation-authoring skill and its required inspection, editing, rendering, and validation workflow. Treat the user's latest deck or supplied template as the visual source.

## Priority

Allocate roughly 70% of design attention to page appearance and 30% to narrative structure.

Preserve factual meaning. Change content only when the user requests rewriting or when shortening is required to prevent visual failure. Keep all shortening faithful to the source.

## Core Workflow

### 1. Reconstruct the Current State

- Locate the latest authoritative deck.
- Inspect every slide before proposing global changes.
- Identify user-confirmed layouts, titles, colors, and page order.
- Classify the request as a global restyle, structural revision, targeted page rebuild, or local alignment repair.
- Preserve slides outside the requested scope.

### 2. Establish the Narrative Spine

- Express the deck's central message in one sentence.
- Assign one clear job to each chapter or section.
- Arrange sections as a deliberate progression such as context, question, evidence, implication, and action.
- Give each slide one narrative role and one audience takeaway.
- Use overview, development, and synthesis pages for complex sections.
- Reorder new slides by narrative function rather than source order or creation time.
- Read all slide titles in sequence; revise them until they form a coherent summary of the deck.

Keep this step concise. Spend detail on page composition after the storyline is stable.

### 3. Audit Page Formation

For every slide, determine:

- What should be seen first?
- What is the single visual center?
- What reading path should the audience follow?
- Is the slide empty, crowded, fragmented, or visually flat?
- Does the slide look like a finished composition?
- Can the audience understand the page within several seconds?

Rebuild the page when the visual center, reading order, and takeaway remain unclear.

### 4. Select a Page Structure

Choose the smallest structure that expresses the relationship:

- Use a flow for sequence or process.
- Use a timeline for change over time.
- Use columns for comparison.
- Use a matrix for repeated mappings.
- Use a hierarchy for levels or ownership.
- Use a central visual with supporting explanations for one dominant concept.
- Use an overview structure when later slides expand several components.
- Use a synthesis structure when a section needs closure.

Prefer one coherent composition over collections of disconnected cards. Use diagrams only when they materially improve understanding.

### 5. Compose the Slide

- Use one concise, audience-facing title.
- Remove subtitles when they duplicate the title or weaken the hierarchy.
- Place supporting content close to the visual element it explains.
- Consolidate minor details into three to five meaningful groups.
- Reduce six or more small steps into broader stages when the page becomes fragmented.
- Keep three to five core results or comparisons visible at once.
- Balance information density with readable whitespace.
- Move body content upward when a removed subtitle leaves unused space.
- Reserve a clear location for the page takeaway when the deck style uses one.

Avoid production notes, content-boundary language, or explanations of how the slide was made.

### 6. Apply a Visual System

Follow the user's palette, template, or brand rules. When none are supplied, infer a restrained professional system from the deck's strongest existing slides.

Maintain consistent:

- Slide margins and grid
- Title position and hierarchy
- Body typography
- Accent-color semantics
- Rule and connector styles
- Image treatment
- Section labels
- Takeaway placement
- Footer behavior

Use body text colors with strong contrast. Use accent colors deliberately for structure, emphasis, data marks, lines, arrows, borders, or nodes.

Reduce repetitive card grids, pills, badges, excessive rounded rectangles, and rigid component-library styling. Favor open layouts, natural grouping, controlled asymmetry, and clear visual balance.

### 7. Normalize Typography and Alignment

- Respect the user's minimum font size.
- Disable automatic text shrinking when it can violate that minimum.
- Shorten text or change layout before reducing font size.
- Keep one-line titles and labels on one line.
- Use comfortable body line spacing; apply approximately 1.4 to 1.5 spacing when the template and available space support it.
- Align row headings with the first line of adjacent content or center them within the row.
- Align corresponding elements across columns.
- Maintain stable gaps between text, rules, borders, arrows, and neighboring modules.
- Prevent connectors and rules from passing through text.

### 8. Decide the Revision Depth

Use a local repair for isolated wrapping, spacing, alignment, font, or overlap problems.

Rebuild the entire slide when any of these conditions apply:

- The title does not state the takeaway.
- The reading order is unclear.
- The visual center is missing.
- The content is divided into too many small fragments.
- Repeated local adjustments fail to create a stable composition.
- The slide visibly departs from the deck's design language.
- The user rejects the title, layout, and information delivery together.

During a targeted rebuild, keep all unaffected slides unchanged.

## Special Page Rules

- Keep title slides minimal.
- Keep agenda slides limited to the agenda unless the user requests more.
- Keep section-divider slides limited to the section identity unless the user requests more.
- Treat overview slides as maps for the pages that follow.
- Treat synthesis slides as conclusions rather than repeated summaries.

## Iterative Editing Rules

- Continue from the user's latest edited version.
- Preserve manual adjustments unless they cause a verified layout problem.
- When the user supplies a screenshot, fix the shown issue and audit the deck for the same pattern.
- When inserting slides, inherit the surrounding design system and verify the new sequence.
- When the user requests one-page changes, avoid unrelated global revisions.
- When a major structural change is required, preserve the source and create a revision copy unless the user explicitly requests in-place editing.

## Validation

Before delivery:

1. Render every slide.
2. Review a contact sheet for deck-level rhythm, density, and style continuity.
3. Inspect every slide at full size.
4. Fix unintended overlap, clipping, wrapping, connector crossings, and alignment errors.
5. Verify minimum font sizes and disable unintended shrink-to-fit behavior.
6. Confirm that titles read as a coherent narrative sequence.
7. Confirm that every slide has a clear visual center and takeaway.
8. Re-render after fixes.
9. Run the presentation overflow and template-fidelity checks when available.

Do not declare completion while any known visual defect remains.

## Completion Standard

Deliver only when the deck satisfies all of the following:

- The main message can be summarized in one sentence.
- Each section has a distinct narrative job.
- Slide order supports a continuous presentation.
- Each slide communicates one primary takeaway.
- Page structures express relationships visually.
- The deck has a consistent visual system.
- Typography is readable and stable.
- Alignment and spacing are intentional.
- New and rebuilt slides belong to the same visual family.
- Unrequested slides remain unchanged.
