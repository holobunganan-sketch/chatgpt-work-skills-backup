# 论文规范排版与洁净交付规范

## 0. 调用含义

调用本 Skill 即表示任务进入投稿交付态。除非用户明确限定为只读检查、纯排版、提纲或中间稿，最终结果必须是可以直接投稿或正式提交的完整成品。问题清单、审计报告、修改建议和格式化半成品均不得替代正式交付。

## 1. 规则等级

- **硬性规则**：可以确定判断且关系到正式交付，违反即阻断。
- **条件规则**：目标期刊或用户模板优先；缺少覆盖要求时执行默认规范。
- **人工门禁**：机器无法可靠识别，必须由整页或图片视觉检查确认。

## 2. 硬性规则

### 2.0 投稿适格逐句门禁

在排版前和最终通读时，对标题、摘要、关键词、正文、题注、脚注、表格单元格和补充材料逐句提出：“如果今天投稿，这句话应该出现在这一章节、这一段、这个位置吗？”

每句话必须满足：

- 符合目标文种的正式语体；
- 承担当前章节和段落的功能；
- 与前后句形成连续的信息或论证关系；
- 服务研究问题、用户指定主张和全文主线；
- 没有编辑语言、协作痕迹、过程说明、内部状态和模型痕迹；
- 没有只为展示谨慎而增加的证据边界说明、自我保护式保留或泛化免责声明；
- 删除后会实质削弱研究信息、论证、可复现性、正式责任或投稿完整性；
- 没有机械复述其他章节。

未通过的句子执行重写、移动、合并或删除。用户只授权排版或只读检查时保持原文，并将发现留在交付目录之外。

### 2.0A 论证方向

- 将用户指定的研究主张、核心判断或倡议作为全文写作目标。
- Introduction 说明问题重要性、现有工作缺口和本研究必要性。
- Discussion 使用最有力且准确的结果、机制、文献联系和实践意义支持核心判断。
- Conclusion 给出清楚、稳健、宏观且前瞻的最终判断。
- 减少无目的的中立综述、反方观点堆叠和立场稀释。
- 不因执行者自身的风险偏好新增“仍需更多研究”等套话。
- 来源稿中的“有人认为结果可能只是偶然”“目前证据仍有限”“尚不能说明”“仍需更多研究”“仍待进一步验证”等表达默认删除，禁止原样继承或换词保留。
- 正式局限必须同时满足四项条件：指向具体的研究设计、样本、测量、统计分析或外部适用性；能够由研究实际情况支持；位于目标文种规定的局限段落；表达简洁且不重复。
- 无法具体说明限制来源和影响路径的泛化保留不得进入成稿。
- 未来研究仅在用户或目标文种需要时提出，必须给出具体研究对象、方法或验证目标，禁止用其撤回已建立的结论。
- 禁止虚构或篡改研究事实、数据、统计结果、引文和来源。

### 2.1 正文

- 文件必须为有效 DOCX。
- 可见文字使用纯黑色。
- 中文使用宋体；英文、数字及英文标点使用 Times New Roman。
- 正文使用 12 磅和 1.5 倍行距。
- 默认页边距为上 2.54 厘米、下 2.54 厘米、左 3.18 厘米、右 3.18 厘米。
- 不使用独立标题页。
- 小标题加粗。
- 连续项目符号达到 5 段时进入人工复核。

### 2.2 默认论文结构

用户和目标期刊均未声明特定写作结构时，正文按 Introduction、Methods、Results、Discussion、Conclusion 的顺序组织。该默认结构包含以下约束：

- Introduction 使用 3 个自然段，章节内部不设置二级及以下小标题。
- Methods 和 Results 可以设置二级小标题；每个二级小标题下使用 1 个自然段。表格、图片、题注和公式不计入自然段数量。
- Discussion 使用 5–7 个自然段，章节内部不设置二级及以下小标题。第一段概括研究问题、所用方法、主要结果和全文意义；最后一段集中声明 1–3 点研究局限。
- Conclusion 使用 1 个自然段，完成宏观、前瞻的总结，不复述 Results 或 Discussion 的内容。
- Methods 描述研究计划采用的方法及每项方法服务的目的。实际入组量、实际筛选量、数据库实际获得记录数及其他研究执行后才能确定的信息不得进入 Methods。
- 计划样本量、样本量估算结果和目标入组量属于研究设计信息，可以进入 Methods，但必须明确使用“计划”“目标”“估算”“预计”等前瞻措辞。
- Results 只报告观察值、估计值、统计检验结果和预先定义分析的输出。原因解释、机制推断、外部文献比较、临床意义判断和延伸思考放入 Discussion。

机器审计检查章节存在性、顺序、小标题层级、可计数的自然段、明显的 Methods 执行后结果、明确的 Results 解释性措辞和结论中的逐句重复。Introduction 或 Discussion 出现二级及以下小标题时直接阻断。Discussion 首段概括范围、局限点数量及 Conclusion 的宏观与前瞻性仍须人工语义复核。

### 2.3 表格

- 使用三线表：表顶线、表头底线和表底线；无竖线和内部横线。
- 文字使用纯黑色。
- 表题位于表格上方并居中。
- P 值列能够明确识别时，`P<0.05` 的项目整行加粗。

### 2.4 图片

- 图题位于图片下方并居中。
- 独立图片使用 PNG，最低 300 dpi。
- 每张图保存为一个独立文件。
- 图内文字使用英文。
- 画布不放标题。
- 使用学术配色并保留宽边缘。

### 2.5 编号与引用

- 图、表、补充图和补充表分别按正文首次出现顺序编号。
- 每个独立图表均在正文中被引用。
- 删除或插入图表后同步更新正文、题注、文件名和补充材料编号。

### 2.6 Zotero

- 最终文稿使用 Zotero 动态引文字段。
- 格式化前后 citation field 和 bibliography field 的载荷、数量和组合关系保持一致。
- 同一引文位置最多包含 4 篇文献。
- 禁止把 Zotero 动态域转换为普通文本。

### 2.7 交付目录

- 只允许手稿、独立图表、补充材料和投稿 Checklist。
- 禁止未登记文件进入正式目录。
- 禁止批注、修订、隐藏文字、过程说明、模型思考过程、用户讨论、内部清单、index、工作记录和审计报告。
- 审计报告与 `delivery-manifest.json` 放在正式目录之外。

## 3. 条件规则

- 用户或目标期刊明确规定页边距时，在项目配置副本中记录四个方向的覆盖值并据此执行与审计。
- 用户和目标期刊均未规定页边距时，使用上 2.54 厘米、下 2.54 厘米、左 3.18 厘米、右 3.18 厘米的默认值。
- 用户对当前任务明确指定非 IMRAD 结构、章节名称、段落数量或章节内容边界时，在项目配置副本中记录覆盖值并据此审计。
- 目标期刊明确指定论文结构且用户未给出冲突要求时，按期刊结构修改项目配置副本。
- 期刊明确规定字体、字号、题注或图片格式时，期刊规则覆盖默认规范，并在项目配置副本中记录覆盖值。
- 现有投稿 Checklist 必须在原文件上保持格式填写。

## 4. 人工门禁

- 逐句检查投稿适格性、章节归属、当前位置、正式语气、论证方向和必要性。
- 检查全文是否持续服务研究问题和用户指定主张。
- 检查自我保护式保留、泛化免责声明和无正式用途的证据边界说明是否已经清除。
- 检查图片配色是否符合学术表达。
- 检查 Discussion 首段是否概括全文且没有展开逐项解释。
- 检查 Discussion 末段是否集中声明 1–3 点局限。
- 检查 Conclusion 是否宏观、前瞻，并与 Results 和 Discussion 无语义重复。
- 检查 Results 是否只报告结果，启发式命中的解释性表达必须逐项确认。
- 检查图内文字是否全部为英文。
- 检查画布是否存在独立标题。
- 检查图片四周是否保留合理宽边缘。
- 检查复杂表头、跨页表格和题注位置。
- 检查整篇 DOCX 是否出现截断、重叠、孤行、异常分页或题注与对象分离。

## 5. 冲突优先级

1. 用户对当前任务的明确要求；
2. 目标期刊正式模板和投稿指南；
3. 用户提供的现有正式模板；
4. 本技能默认规范；
5. 自动审计的启发式判断。

自动脚本不得覆盖人工语义判断。遇到字段保护失败、文件损坏或规则冲突时停止格式化，保留源文件并报告具体对象。
