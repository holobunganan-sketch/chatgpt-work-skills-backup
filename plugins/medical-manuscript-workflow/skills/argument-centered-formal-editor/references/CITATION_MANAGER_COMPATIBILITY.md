## 1. 适用范围

正文已经含有 Zotero 或其他引文管理器生成的引文时，使用本规范保护引用结构。本规范覆盖：

- Word 中的动态引文域；
- Markdown 中的 Pandoc citation key，如 `[@key]` 或 `[@key1; @key2]`；
- LaTeX 中的 `\cite{key}` 等引文命令；
- 数字编号、作者—年份标识及其现有映射；
- 用户提供的其他机器可解析引用占位符。

## 2. 职责分离

本技能负责：

- 判断现有引文承担的论证任务；
- 让引文紧邻其所支持的最小陈述；
- 在重组句段时保持引用对象完整；
- 检查引文移动后是否仍与主张对应。

本技能不执行：

- 检索引文管理器文库；
- 选择或替换文献条目；
- 创建新的 citation key 或动态引文域；
- 同步、导入或修改文献库；
- 改变引文样式；
- 生成或刷新参考文献表。

这些操作由用户指定的引文管理器流程完成。

## 3. 受保护对象

开始编辑前记录全部引用标识及其数量。把以下内容作为不可改写的原子对象：

- citation key 及其大小写；
- LaTeX 引文命令中的键值；
- Word 动态引文域及其内部载荷；
- 既有数字编号或作者—年份标识；
- 引文管理器与参考文献表之间的映射。

正文重写不得手工改写 citation key，不得展开或清理 Word 域代码，不得把动态引文转成普通文本。

## 4. 重写中的引用定位

引用位置服从证据任务：

1. 确认引文当前支持的最小陈述；
2. 重写该陈述及其上下文；
3. 让引文随受支持的陈述共同移动；
4. 检查引文前后的主体、术语和判断方向；
5. 检查引文与邻近的其他主张是否产生错误归属。

一个句子拆成多个主张时，把现有引文保留在其原有支持内容对应的主张后。多个句子合并时，保留全部原有引用对象，并按照各自支持的具体成分定位。来源支持关系不清时，保持原位置并把问题留给上游引文管理流程。

## 5. 各格式处理

### 5.1 Markdown

- 完整保留 `[@key]`、`[@key1; @key2]` 及前缀、后缀、页码信息；
- 不改写 key；
- 不拆散组合引文；
- 重写前后比较 citation key 集合与数量。

### 5.2 LaTeX

- 完整保留引文命令、可选参数和 key；
- 不把引文命令转换成普通文本；
- 重写前后比较 key 集合与数量；
- 命令类型和样式由现有项目约定控制。

### 5.3 DOCX

- 把 Zotero 动态引文视为不可改写对象；
- 移动句段时让动态引文与受支持文本共同移动；
- 不编辑域代码、CSL 载荷或显示文本；
- 不把动态引文扁平化为普通文本；
- 完成编辑后由 Zotero Word 插件执行刷新和完整性检查。

### 5.4 纯文本或其他格式

- 保留现有编号、作者—年份标识和占位符；
- 记录无法可靠识别的引用对象；
- 避免根据视觉形式猜测底层文献映射。

## 6. 完成检查

- [ ] 编辑前后的引用标识集合一致，用户明确要求删除或新增的情况已经单独记录。
- [ ] citation key、域代码和动态引文没有被改写或扁平化。
- [ ] 每项移动过的引文仍紧邻其所支持的最小陈述。
- [ ] 合并或拆分句子后没有产生错误引用归属。
- [ ] 本技能没有调用文库检索、条目选择、文献同步或样式更新流程。
- [ ] DOCX 动态引文已经留给 Zotero Word 插件刷新验证。
