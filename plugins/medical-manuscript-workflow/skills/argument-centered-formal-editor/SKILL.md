# 主线驱动正式写作

## 核心目标

让全文持续回答同一个核心问题。让每段交付一个明确判断，让每项引用完成一项读者能够复述的论证任务，让相邻句段通过具体关系推进。

把下列结果设为强制要求：

- 读者能够说明每项证据为何出现在当前位置。
- 引证前后的主体、术语、语气、抽象层级和句法节奏保持连续。
- 承接句完成解释、比较、递进、因果、例证、归纳或导向下一判断中的至少一项任务。
- 学术文本优先写明研究对象、变量、行为、条件、变化方向和结果，压缩无具体指向的抽象名词。
- 保留原有事实、数据、引用标识、受控术语和作者已经建立的有效判断。
- 编辑深度服从论证修复需要。局部修句无法恢复推理时，重编译句群、段落或相邻段落。

## 责任范围

把来源核验、证据等级和支持范围视为上游已经完成的工作。本技能处理证据在文章中的功能、位置、表达、承接和全文贡献。

禁止在编辑过程中主动增加：

- 证据边界说明；
- 限制条款；
- 预先回应质疑的防御性句子；
- 面向审稿人、反馈者或内部人员的处理说明。

保留用户明确要求保留的原有内容。目标段落中的证据边界、限制条款和防御性说明不得作为证据整合的一部分继续保留；用户明确要求编辑限制章节时，按照该章节任务处理。不得凭编辑需要补造事实、数据、来源或引用。

## 执行流程

### 1. 读取全文并建立工作视图

读取正文、引用材料、反馈、格式要求和用户明确决定。先判断文档目的、核心问题、目标结论、作者声音和必须保留的内容。

短段落可以在内部完成工作视图。长文、跨章节修改、多来源整合或多方反馈任务使用 [editing-brief.template.json](assets/editing-brief.template.json)；需要机器检查时同时使用 [argument-evidence-map.schema.json](assets/argument-evidence-map.schema.json)。

正文含有 Zotero 或其他引文管理器生成的 citation key、域代码、动态引文或文献映射时，把这些对象登记为受保护的引用标识，并读取 [CITATION_MANAGER_COMPATIBILITY.md](references/CITATION_MANAGER_COMPATIBILITY.md)。本技能不主动检索文库、选择条目、插入新引文、同步参考文献库或改变引文样式。

### 2. 恢复可修订主线

用一至三句话写出全文需要读者接受的答案，再标出从核心问题到答案的必要节点。允许线性推进、分支比较、问题—方案、规则—适用、时间—因果和多项发现汇合。

先形成可修订骨架。不要提前把骨架扩写成完整正文。遇到来源材料时，允许保持主线、补足局部节点或调整局部关系。只在调整能够提高全文流畅度与严谨性时修改主线。

处理复杂证据与主线关系时读取 [MAINLINE_EVIDENCE_CO_DESIGN.md](references/MAINLINE_EVIDENCE_CO_DESIGN.md)。

### 3. 判断编辑深度

根据问题选择最小达标层级：

1. 词语或指代；
2. 单句；
3. 句群；
4. 整段；
5. 相邻段落；
6. 章节。

把“达标”定义为主线、段落判断和证据任务均已清楚。发现引用改变叙述主体、段落按来源顺序排列、句序可任意交换、段末结论缺少前文铺垫时，至少重编译相关句群或整段。

### 4. 按契合度处理来源叙事

逐项判断来源叙事与本文当前任务的契合程度：

- **高度契合**：保留原有叙事关系，完成必要的术语、指代、语序和引用位置调整。
- **部分契合**：保留可用关系，按照本文主体和段落判断重新组织。
- **局部可用**：提取能够推进本文的最小命题或具体关系，舍弃来源自身的无关叙事。
- **无推进作用**：不写入正文。

不要把来源改写设为固定动作。不要为了展示整合过程而改变已经自然契合的表述。

执行具体判断时读取 [SOURCE_TO_ARGUMENT_TRANSFORMATION.md](references/SOURCE_TO_ARGUMENT_TRANSFORMATION.md)。

### 5. 为每项证据指定论证任务

让每项进入正文的证据至少完成一项任务：

- 建立事实；
- 量化现象；
- 解释结果；
- 比较一致或差异；
- 补足两个判断之间的推理；
- 区分竞争性解释；
- 把研究发现连接到当前问题；
- 支持后续判断或行动。

记录证据服务的段落判断、进入点、完成的任务和后续去向。证据只有主题相关性时，将其留在材料池或删除。

两项及以上来源承担同一任务时，先综合共同判断，再合并引用或把引用放在各自对应的具体成分之后。禁止保留连续的“作者—发现—引用”句列。只有研究差异本身属于当前判断时，才分别以研究为主体展开。

### 6. 构建推理桥

在内部写清：

`上文已建立什么 → 当前缺少什么 → 证据加入什么 → 本文据此推进到什么 → 下一句或下一段继续什么`

允许一个句子融合多个环节，允许多项证据共同完成一个环节。正文不得机械重复“某研究发现……这表明……”。

证据句已经完成局部推理时，不得追加同义复述。作者推进必须导向新的局部判断或后续节点；无法继续推进时，融合或删除重复句。

作者推进可以补足材料已经允许的逻辑关系。不得把材料未提供的干预构成、执行步骤、机制或结果写成既定事实。推理需要具体，新增细节必须有原文或来源依据。

避免在证据出现前提前写完证据将要导出的判断。优先按照“已知问题或发现 → 证据贡献 → 本文推进”组织。相邻句共享同一主体和谓语、后一句只增加引用标识时，合并两句。

执行句段承接、语气对齐和具体化改写时读取 [INFERENCE_BRIDGES_AND_VOICE_ALIGNMENT.md](references/INFERENCE_BRIDGES_AND_VOICE_ALIGNMENT.md)。

### 7. 重编译段落和相邻段落

按照读者完成推理的顺序生成正文。优先使用明确主体、具体谓语、比较对象、变化方向和结果建立关系。连接词只标记已经存在的关系。

逐段检查：

- 本段交付的判断能否用一句话复述；
- 每句是否改变、解释、量化或推进当前判断；
- 引证句是否延续本文视角；
- 删除引用标识后，句义是否仍能显示证据任务；
- 删除证据内容后，是否有一项具体推理中断；
- 调换句序后，论证是否明显受损；
- 是否残留逐篇摘要、材料陈列或抽象空话。
- 是否出现“提前给出判断—引证重复—再次总结判断”的回环。
- 是否保留了与当前段落任务无关的证据边界、限制条款或防御性尾句。

### 8. 按主线整合反馈

把反馈映射到相关主线节点和段落任务。合并指向同一问题的反馈，在正文最自然的位置完成一次协调修改。

禁止按照反馈编号增加句子或小节。禁止把修改过程、作者决策过程和待办事项写入正文。

### 9. 执行全文验证

读取 [SPEC.md](references/SPEC.md) 完成规范门禁。学术、政策、商业、技术或法律任务仅读取 [DOMAIN_PROFILES.md](references/DOMAIN_PROFILES.md) 中对应部分。

对文本运行：

```bash
python scripts/scan_argument_flow_risks.py <文件路径>
```

对已填写的工作图运行：

```bash
python scripts/validate_argument_evidence_map.py <工作图.json>
```

需要比较修改前后结构时运行：

```bash
python scripts/compare_revision.py <原文> <修订稿>
```

把脚本结果视为复核候选。结合全文语义作最终判断。

### 10. 只交付成品

输出最终正文。只有用户明确要求时才附修改说明、主线图或风险记录。内部工作图、来源适配判断、推理桥和反馈映射不得自动进入正式文本。

## 完成门禁

完成前确认：

- [ ] 全文核心问题和目标答案清楚。
- [ ] 每段交付一个可复述的判断。
- [ ] 每项引用承担明确论证任务。
- [ ] 来源叙事处理程度与契合度一致。
- [ ] 主线调整具有全文收益；无收益的调整已经撤销。
- [ ] 承接来自具体推理关系。
- [ ] 学术文本已经压缩无指向的抽象表达。
- [ ] 引证处没有主体、术语、语气或节奏突变。
- [ ] 段落顺序服从推理顺序。
- [ ] 修改深度足以解决问题。
- [ ] 事实、数据、引用标识和受控术语未被改坏。
- [ ] 改写目标段落没有保留或新增证据边界、限制条款或防御性说明。
- [ ] 正文没有内部过程、反馈痕迹或待办内容。
- [ ] 外部引文管理器生成的 citation key、域代码和动态引文保持完整。
- [ ] 移动过的引文仍紧邻其所支持的最小陈述。
- [ ] 本技能没有主动改变引文样式、文献库或参考文献映射。
